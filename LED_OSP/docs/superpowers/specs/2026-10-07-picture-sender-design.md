# Windows 图片发送软件与连续接收设计

日期：2026-10-07。状态：用户选择自动搜索设备，按下述方案实施。

## 用户要完成的操作

电脑和 ESP8266 接入同一局域网，在窗口中选择图片，看到实际将发送的黑白效果，
选择 W25Q128 图片编号，点击发送。再次选择图片或再次启动软件都不需要复位开发板。
软件自动搜索活动 IPv4 网卡所在局域网，显示识别到的墨水屏设备供选择，
默认不需要输入 IP。软件记住上次设备、端口和图像处理选项。

## 连接方案比较

1. 推荐：ESP8266 持续运行 TCP 服务器，电脑软件作为客户端连接开发板 IP。
   电脑 IP 改变不需要重新编译开发板。发送结束可以关闭连接，下一次发送重新连接。
2. 保留现有方向：电脑监听，开发板自动重连电脑。变动较少，但开发板仍依赖电脑 IP。
   不适合用户希望换电脑也能直接使用的目标。
3. 用户选择：在推荐方案上加入自动搜索设备。软件读取活动网卡真实 IPv4 前缀，
   在局域网内并发查询指定端口，并通过专用 INFO 应答识别墨水屏。
   查询本身不擦写 Flash。搜索可取消；不搜索公网或无连接的网卡。
   超大网段限制扫描数量并显示范围，保留高级手动地址入口，避免长时间占满网络。

## 电脑窗口

- 单个中文 Windows 窗口，提供双击启动入口，使用本机已有的 Python、Tkinter 和 Pillow。
- 原图和 800×480 黑白预览并列；预览直接从将发送的 48000 字节像素生成，避免预览与数据不同。
- 选择 PNG、JPG、BMP 等 Pillow 支持的常见图片，也允许已有的 48000 字节像素 BIN。
- 图片适配：完整显示并补白、等比例裁剪填满、拉伸。默认保留现有的完整显示行为。
- 黑白阈值 0～255，以及抖动开关。开启抖动时阈值控件禁用，避免产生无效设置。
- 搜索设备、设备选择列表、端口（默认 8080）、图片编号（0～255）。默认不填写 IP。
  高级手动地址可用于自动搜索未覆盖的大网段；不需要填写电脑 IP。
- 选择图片、发送、取消；显示连接、准备 Flash、正文进度、保存结果及简短错误信息。
- 发送和转换不阻塞窗口。发送时使用点击发送瞬间的图片和选项，禁止中途更换发送参数。
- 取消时关闭本次 socket，使正在等待应答的后台线程退出；下次发送从包头重新开始。
- 收到 DONE 显示“保存完成”。现有协议不确认物理屏幕刷新结束，不能显示“屏幕刷新完成”。
- 本轮先提供一键启动软件和源文件；独立 EXE 打包在界面和传输验证后处理。

## 开发板连接与接收

- ESP8266 连接已有 Wi-Fi 后，通过 LwESP 启用 TCP 服务器，监听 8080。
  Wi-Fi 配置仍在 USER/app_config.h，电脑地址不再参与默认服务器模式。
- 下载队列和 FW_TCP 任务只创建一次，监听保持运行。每次连接都建立新的接收会话。
- 同一连接允许连续传多张图片；关闭后允许新连接再次发送。
- 正常关闭、取消、错误或超时，结束当前接收并重新待命；不需要重新初始化 MCU。
- 回调只记录连接事件、复制接收数据并归还 LwESP 缓冲；Flash 操作和阻塞应答仍由 FW_TCP 执行。
- 每项接收数据关联会话编号；新连接复用旧连接对象时，也不能接收旧会话队列里剩下的数据。
  解析对象只由下载任务重置，避免回调在另一个任务写 Flash 时清空对象。
- 同时只接收一个发送者，其他连接不参与写入。连接关闭不能撤销已经提交的图片或固件。
- LwESP 的最大连接数设置不能代替应用层门禁；旧 AT 固件可能忽略该设置。
  额外连接的建立、数据和关闭事件不能更改当前会话。
- 应答核对会话身份和非阻塞发送入队放在同一段短 LwESP 核心锁内，
  使用持续有效的应答缓冲和发送完成事件通知下载任务；不在核心锁内等待发送完成。
  这样旧会话的 READY/ACK/DONE 不会发给复用相同连接对象的新会话。
- 固件停止必须检查 Abort 的返回结果；清理失败时保留正在被固件层引用的状态对象，
  不通过清空该对象来强行接纳新下载。图片取消按原规则废弃未提交会话。
- 原有未收完整、CRC 错误、Flash 读写错误等校验继续生效；下载失败不能发布有效图片。
- 不重新初始化屏幕或 Flash 分区；显示继续使用已经验证的 EPD_ShowPicture() 流程。
- 原固件候选存储功能保持，原命令行工具增加连接开发板 IP 的用法。
  本轮不新增 Bootloader 安装、自动复位、MQTT 或云端下载功能。

## 数据流与协议

选择图片 → 生成黑白像素和预览 → 电脑连接开发板 → 发送 PIC1 包头 →
等待 READY → 发送最多 256 字节正文并等待累计 ACK → 等待 DONE →
电脑关闭本次连接；开发板投递屏幕显示请求并等待下一次连接。

继续使用既有 PIC1 32 字节小端包头、CRC32、READY/ACK/DONE，图片仍为
800×480、1 bit/pixel、1 白 0 黑、每字节高位在左。固件 FWUP 包格式不改变。
GUI 与命令行复用图像转换及发送核心，网络代码不依赖 Tkinter。

增加只读设备查询：电脑发送 ASCII 四字节 INFO，开发板回复
`EPD1 800 480 256\r\n`。软件校验完整应答再把设备列入结果；
接收端允许查询拆包，查询不调用固件或图片擦写接口，查询结束后可以断开。

## 验证与交付

1. 像素测试验证补白、裁剪、拉伸、透明图、原始 BIN 和预览/发送像素一致。
2. 本机 TCP 模拟开发板验证应答分片、异常 ACK、ERR、掉线、超时、取消和重复发送。
3. 实际 C 下载任务测试验证连续连接、取消后重新连接、旧队列隔离、连接对象复用、
   旧会话应答隔离、第二个客户端隔离、提交保留，以及固件清理失败时的对象保护。
4. 运行既有主机回归，确保图片、A/B 固件、SPI、串口、屏幕和日志功能继续通过。
5. Keil 编译并生成含 OpenBLT 校验字的 App HEX，明确交付需要烧录的文件。
6. 启动真实 GUI 核对预览、控件和状态；真实开发板效果仍由用户烧录后确认。

最终提供双击启动入口、软件文件、中文使用说明、新 App HEX，以及明确的软件与开发板测试结果。
