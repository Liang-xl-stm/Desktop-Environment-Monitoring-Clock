# TCP 发送图片到 W25Q128 并显示

## 最短测试流程

1. 用 ST-Link 烧录新的 `OBJ/LED_OSP_openblt.hex`，这是 App，地址仍为 0x08020000。
2. 电脑与开发板连接同一 Wi-Fi 或热点，等待开发板启动 TCP 服务器。
3. 安装 Python 和 Pillow，运行 `Tools/启动图片发送器.vbs` 或 `python Tools/picture_sender_gui.pyw`，软件会自动搜索开发板。
4. 选择图片，在右侧检查整体预览，选择图片编号，然后点击“发送到屏幕”。保存完成后可继续发送下一张，无需复位。
5. 电脑显示保存完成表示 Flash 保存成功；串口出现 `picture slot=0 shown, sleeping` 表示刷新完成。

命令行也支持直接连接开发板，例如开发板 IP 为 172.20.10.3：

   ```text
   python Tools/send_picture.py "D:/照片/风景.jpg" --slot 0 --host 172.20.10.3
   ```

未填写 `--host` 时，命令行工具保留电脑监听模式，供旧版 TCP 客户端固件使用。
当前开发板是 TCP 服务器，使用自动搜索软件或填写 `--host`。

项目附带测试图片 `Tools/Pictures/test_picture.png`，可先用它验证黑白方向和画面位置。
首次同时烧录 Bootloader 和 App 可用新生成的 `OBJ/Bootloader_App.hex`。
以上文件生成不会自动烧录硬件，本次实际屏幕效果仍需上板验证。

## 预览与实屏观感

发送的是 800×480 的黑白点阵。勾选抖动时，通过细小黑白点的比例表现灰度，
因此人像的脸、背景和头发可能整体呈灰色，不是所有深色区域都会变成整块黑色。
软件“整体预览”先转成灰度，再平滑缩放，避免取样时丢点造成灰度失真；
双击预览可查看 800×480 原始点阵，原尺寸点阵和发送数据完全一致。
缩放只影响窗口中的显示，不改变发给开发板的 48000 字节。

电脑预览不能保证与实屏光学观感完全一致。墨水屏依赖环境光，屏幕底色、黑色反射、
照明和观察距离都会影响结果。若希望更明确的黑白块，可关闭抖动后调整黑白阈值，
但会失去灰阶细节。不要仅凭预览对比去修改屏幕驱动电压或波形。

`Tools/Pictures/contrast_test.png` 是 800×480 对照图，上半部分为纯黑和纯白，
下半部分依次为 25%、50%、75% 黑点覆盖率。用软件选择该图发送，
可检查大块黑色与灰度点阵的区别；同样遵循所选图片编号覆盖规则。

## 工具参数

| 参数 | 用途 |
| --- | --- |
| 一个或多个图片路径 | PNG/JPG/BMP 自动转换；48000 字节 BIN 按原格式发送 |
| `--slot 0` | 第一张图的编号；多图依次递增，整个范围必须在 0～255 |
| `--threshold 128` | 默认黑白阈值，0～255；灰度大于等于此值为白 |
| `--dither` | 对照片使用黑白抖动，保留更多灰阶观感 |
| `--host 开发板IP` | 直接连接开发板，可反复运行，不需要复位 |
| `--port 8080` | 开发板 TCP 端口，与 TCP_SERVER_PORT 一致；旧监听模式使用电脑端口 |
| `--bind 0.0.0.0` | 监听地址，默认监听所有本地网卡 |
| `--prepare-only` | 仅生成 BIN 和 PNG 预览，不开启 TCP 监听 |
| `--output-dir 路径` | 转换结果目录，默认 OBJ/pictures |

示例：`python Tools/send_picture.py a.png b.jpg --slot 3 --dither --host 172.20.10.3`，上传到 3、4 号槽。
多图保存后屏幕优先显示最近一次请求；所有已保存图片都能按编号再次读取。
每次工具运行结束会关闭这次 TCP 连接，开发板继续监听；下次发送可直接再次连接。
同一编号会替换旧图，覆盖失败可能使该槽旧图失效。

## 开发板简单调用

```c
#include "epd_app.h"

/* 普通任务调用：参数是图片编号，不是 Flash 地址。
 * 返回 1：显示请求已投递；0：参数越界、屏幕任务关闭或错误上下文。
 * 函数立即返回，实际读取及刷新由 EPD 任务完成，结果查看串口日志。
 */
uint8_t queued = EPD_ShowPicture(3U);
```

上电默认显示 0 号图，修改 `USER/epd_config.h` 的 `EPD_STARTUP_PICTURE` 可换其他编号。
不要在其他任务直接调用原屏幕刷新函数；如需这样做，先关闭 EPD_TASK_ENABLE。
存储接口和每个参数说明在 `Application/Picture/picture_store.h`。

## 图片数据和地址

图片固定 800×480，1 bit/pixel，48000 字节。每行 100 字节，按行从上到下排列，
每字节高位表示左侧像素；1 白、0 黑。PNG/JPG 文件不能直接作为屏幕像素发送。
转换工具自动处理 EXIF 方向、透明白底及等比例缩放，余下区域补白。

图片区为 0x300000～0xFFFFFF，共 13MiB，分成 256 个 52KiB 槽。
槽 n 起点：`0x300000 + n * 0xD000`。
每槽前 4096 字节为管理扇区，正文从槽起点 +4096 开始；正文尾部留有擦除对齐填充。
前面的固件 A/B、两份管理记录以及自检区不作为图片地址使用。

保存顺序：擦除并读回验证管理扇区 → 擦除正文扇区 → 顺序写正文 →
读回 CRC32 → 写管理信息并核对 → 最后写有效标记并核对。
未收齐正文或正文 CRC 不一致时不能发布有效新图。
若有效标记已经写入，仅最后读回或网络应答失败，图片可能已保存；读回校验结果才是判断依据。
读取显示再次验证管理记录及整个正文 CRC，读取失败的数据不交给屏幕。
屏幕只使用一个静态 48000 字节缓冲，更新和显示通过原 Flash 总线锁协调。

## TCP 包格式

32 字节包头，每项 uint32 小端：

| 偏移 | 内容 |
| --- | --- |
| 0 | magic=0x31434950，小端为 PIC1 |
| 4 | version=1 |
| 8 | 图片槽号 0～255 |
| 12 | width=800 |
| 16 | height=480 |
| 20 | length=48000 |
| 24 | 正文 CRC-32/ISO-HDLC，与 zlib.crc32 一致 |
| 28 | reserved=0 |

发送包头 → 等 READY → 每次最多 256 字节正文 → 等累计 ACK → 最后等 DONE。
DONE 后可以再发下一张图；屏幕显示异步进行，DONE 不是屏幕刷新确认。
原 FWUP 协议与固件工具保持兼容。固件基线未就绪时拒绝 FWUP，Flash 可用时仍能接收 PIC1。
回调只复制数据，不等待 Flash 擦除、CRC 或屏幕刷新。

## 下载失败时查看日志

发送工具出现 `ERR` 时，图片未获得保存确认，不会发起新图显示。
串口报告失败阶段、成功写入字节数和 Flash 地址；正文开始前失败还会打印实际包头。
例如 `ERR PIC_PREPARE META_ERASE` 表示图片槽管理扇区擦除失败。

| 阶段 | 含义 |
| --- | --- |
| HEADER_MAGIC / PIC_HEADER | 包类型或图片参数不符合协议 |
| PIC_PREPARE META_ERASE / BODY_ERASE | 管理或正文扇区擦除失败 |
| PIC_PREPARE META_READ / META_NOT_ERASED | 擦除后读取失败或仍有非 FF 数据 |
| PIC_WRITE BODY_WRITE | 正文编程失败 |
| PIC_FINISH BODY_READ / BODY_CRC | 正文读回失败或 CRC 不匹配 |
| PIC_FINISH META_* / COMMIT_* | 管理记录或有效标记写入、读回核对失败 |

SPI 的 TXE、RXNE、BSY 各等待阶段独立计时，预算分别为 1 ms。
RXNE 从发送字节后开始计时，避免发送前任务切换用尽接收等待预算。
超时判断先检查实际完成标志，并在截止时重新读取标志，
避免其他任务运行时，将已完成的硬件传输误判为超时。
真实外设卡死和硬件错误仍会中止当前事务。

图片存储失败后还输出最近一次 SPI 故障快照，保存于复位 SPI1 之前：
`fault=3` 为计数器不可用，`4` 为超时，`5` 为硬件错误；
`phase=1/2/3` 分别对应 TXE/RXNE/BSY，`SR/CR1` 为当时的寄存器，
`cycles` 为该阶段等待周期数，`DWT=1` 为周期计数已开启。
`fault=0` 表示尚无总线错误；成功操作不清除历史快照，后续失败会覆盖。
随后输出的 Flash `SR1=00` 只表示采样时 Flash 空闲，不能排除此前的 SPI 失败。

启动时没有有效的 0 号图片，会显示黑方框测试图案。
必须先看到 `slot=0 stored, CRC OK` 和电脑 `DONE`，才会投递新图显示；
下载失败时继续显示原画面，不代表屏幕刷新驱动失败。

USART3 中断每收到有效字节就发布给 ESP_RX，不等到 255 字节缓存满或 IDLE。
256 字节正文加 AT 头可能是一段连续串口数据；等满才发布会让后续字节在任务醒来前丢失，
导致正文解析和 ACK 等待停住。发送工具在收到 READY 时显示 Flash ready；
若超时，会报告正在等待的 ACK 累计字节数和已确认进度。
